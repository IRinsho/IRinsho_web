# 云端后台 · 配置教程（照着点就行）

> 这份教程只做一件事：把云端后台需要的**三个配置**填好。
> 你的仓库是 **私有** 的，所以第 1 步里那句「授权给这个仓库」千万别漏，不然 Token 建了也用不了。
>
> 预计耗时：**8 分钟**。

---

## 开始之前，先核对这 4 个值

后面到处要用，先看一眼：

| 项目 | 你的值 |
| --- | --- |
| GitHub 用户名 | `IRinsho` |
| 仓库名 | `IRinsho_web` |
| 分支 | `main` |
| 仓库可见性 | **私有** |

# 第 1 步：建 GitHub Token（约 4 分钟）

> 这一步是给后台一把**只能开你仓库这一把锁**的钥匙。
> 它比"账号密码"安全得多——即使泄露，也只能改你这一个仓库，不能碰你账号里别的东西。

### 1.1 打开创建页面

浏览器地址栏直接粘这一行：

```
https://github.com/settings/personal-access-tokens/new
```

如果打不开或跳到了登录页，就手动点：
**右上角头像 → Settings → 左侧最底 Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**

### 1.2 填写基本信息

| 字段 | 填什么 |
| --- | --- |
| **Token name** | `irinsho-admin` |
| **Expiration** | 选 **No expiration**（不设过期） |
| **Description** | 随便写，比如 `我的网站后台` |

> **为什么选不过期**：如果设了 30 天，到期那天后台会突然打不开，你还得回来找原因。
> 想更安全可以设 90 天，但要记得到期前重建一个。

### 1.3 选仓库（**关键，别漏**）

**Repository access** 这一栏，选：

```
○ Public repositories
● Only select repositories     ← 选这个
```

选完之后下面会出现一个下拉框 **Select repositories**，点它，**勾选 `IRinsho_web`**。

> ⚠️ 这一步最容易漏。你的仓库是私有的，不在这里勾上，Token 就没有它的权限，
> 后台保存时会报 `404` 或 `403`。

### 1.4 给权限（只改一个）

往下滚到 **Permissions**，展开 **Repository permissions**，找到 **Contents**：

```
Contents   →  改成  Read and write
```

改完之后上下几行会自动变色：

| 权限 | 会自动变成 | 要不要管 |
| --- | --- | --- |
| **Metadata** | Read-only | 必须的，不用手动改（它是必选项） |
| **Contents** | **Read and write** | ← 只有这个要你手动改 |

**其它权限一个都不要给。** 后台只需要读写文件这一项。

### 1.5 生成并复制

1. 点最下面的绿色按钮 **Generate token**
2. 页面顶部会出现一串 `github_pat_` 开头的字符
3. **点右边的复制按钮**

> ⚠️ **这串东西只显示这一次**，关掉页面就再也看不到了。
> 先粘到记事本里存着（下一步要用）。它等于你仓库的钥匙——
> **不要发给任何人、不要写进代码、不要截图发出来。**

# 第 2 步：在 EdgeOne 里填写环境变量（约 3 分钟）

> 这一步是把刚才那串钥匙，**安全地**交给 EdgeOne 的服务器保管。
> 它不会出现在你的网页代码里，别人翻你的网站源码也看不到。

### 2.1 找到入口

EdgeOne 控制台 → 你的项目 **`irinshoweb`** → **项目设置** → **环境管理**（或叫「环境变量」）

### 2.2 新增 4 个变量

点「新建」/「添加变量」，逐个填这 4 行（**名字必须一模一样，大小写都要对上**）：

| 变量名（Key） | 值（Value） |
| --- | --- |
| `GITHUB_TOKEN` | 第 1 步复制的那串 `github_pat_...` |
| `GITHUB_OWNER` | `IRinsho` |
| `GITHUB_REPO` | `IRinsho_web` |
| `GITHUB_BRANCH` | `main` |

### 2.3 几个容易出错的点

- 值**前后不要有空格**（粘的时候容易带上）
- 4 个都要填，缺一个后台就会报错并告诉你缺哪个
- 如果控制台区分「生产 / 预览」环境，填在 **生产** 里
- 如果它让你选"变量类型"，选**加密 / 密钥**类型（如果只有普通类型，普通也行）

> 📌 **重要**：官方文档写明 —— **环境变量的改动只对新的部署生效**。
> 所以填完先别关页面，第 4 步会触发一次新部署。

# 第 3 步：Blob 存储 —— 什么都不用做 ✅

> 这一步**不需要你操作**。原本我以为要手动建命名空间，但 EdgeOne 自己的
> Blob 页面写着：**「通过 Blob SDK 首次调用即自动创建，无需手动配置」**，
> 而且**控制台只能只读浏览，写操作全部通过 SDK 完成**。
>
> 后台代码里已经写死了命名空间名字 **`irinsho-admin`**，
> 第一次有人打开后台时，平台会自动把它建出来。

## 你怎么知道它成功了

部署完打开后台，看顶部**有没有一条黄色警告**：

| 看到什么 | 意思 | 怎么办 |
| --- | --- | --- |
| 没有警告 | ✅ 存储正常，密码会持久保存 | 什么都不用做 |
| 黄色警告：「会话存储没连上 Blob…」 | ❌ SDK 没装上或 Namespace 没建起来 | 见下面 |

**如果有黄色警告**，按顺序查：

1. **先看项目依赖**：`package.json` 的 `dependencies` 里应该有
   `"@edgeone/pages-blob": "^0.0.18"`，而且 `package-lock.json` 已经提交进 git。
   缺了就补上再推一次。
2. **再看构建日志**：EdgeOne 的「构建部署」页面，翻这次构建的日志，
   搜 `pages-blob`，确认依赖装上了（没装上的话构建日志里会有 npm 报错）。
3. **最后去控制台看一眼**：左侧 **存储 → Blob**，
   里面应该出现一个名叫 `irinsho-admin` 的命名空间（它是 SDK 自动建的，你只能看不能改）。
   如果什么都没有，说明函数根本没成功跑起来——去看函数日志。

> 💡 就算这条警告一直在，后台**依然能用**，只是密码存在内存里，
> 服务器重启后你要重新设一次密码。内容读写完全不受影响。

等这次构建变成「成功」。

# 部署完之后怎么验证

## 1. 打开后台

```
https://irinsho.top/admin/
```

第一次会让你**设置密码**（至少 6 位）。这个密码存进 Blob 存储，**明文不保存、也不会进 GitHub**。

> 忘了密码：去 EdgeOne 的 Blob 存储里删掉 `auth/password.json`，再打开就会让你重设。

## 2. 进去后应该看到什么

- **仪表盘**：笔记数量（应该是 12 篇左右）
- 顶部一块蓝框写着：**内容保存在 GitHub 仓库 `IRinsho/IRinsho_web@main`**
- **没有**那条黄色的 Blob 警告

## 3. 试一次真实保存

1. 点 **笔记** → 随便打开一篇
2. 在正文末尾随便打个字
3. 点右上角 **保存（提交）**
4. 去 GitHub 仓库页面刷新，应该能看到一条新的提交记录
5. 等 1～3 分钟，网站自动更新

**这就算全通了。**

# 出问题对照表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 打开 `/admin/` 是 404 | 构建时没带上 `node-functions/admin/` | 看构建日志；确认这次构建成功 |
| 页面能开，提示「连不上后台」 | 函数没部署成功 | 浏览器 F12 → Network → 看 `/api/admin/session` 的状态码 |
| 提示「缺少 `GITHUB_TOKEN`」 | 环境变量没配对，或没重新部署 | 核对变量名拼写（区分大小写）→ 重新部署 |
| 提示 `GitHub API 出错（401）` | Token 过期或复制时漏字符 | 重新生成一个 Token，仔细复制 |
| 提示 `GitHub API 出错（403）` | Token 没给 Contents 写权限 | 回第 1.4 步，确认 Contents = Read and write |
| 提示 `GitHub API 出错（404）` | 仓库名/分支写错，**或 Token 没授权这个私有仓库** | 核对 `GITHUB_OWNER`/`GITHUB_REPO`/`GITHUB_BRANCH`；回第 1.3 步确认勾了 `IRinsho_web` |
| 每次重启都要重设密码 | Blob 没连上（SDK 没装 / 函数没跑起来） | 看后台顶部黄色警告，按第 3 步的三条顺序查 |
| 保存成功但网站没变 | 构建还没跑完，或构建失败 | 去「构建部署」页面看状态和日志 |
| 手机上排版乱 | — | 告诉我，我调 |

# 常见疑问

**Q：这串 Token 会不会泄露？**
不会出现在网页里。它只存在 EdgeOne 服务器的环境变量里，你网站的访客看不到。
但**你不要把它发给任何人**（包括不要发给我）。如果你怀疑泄露了，去 GitHub 把它
**Revoke（撤销）**，重新建一个，然后在 EdgeOne 里换掉那个值。

**Q：以后我想换 Token 怎么办？**
回第 1 步建个新的，在 EdgeOne 环境变量里改 `GITHUB_TOKEN` 的值，然后重新部署一次。

**Q：免费额度够吗？**
Blob 存储免费额度 1 GB，你只存一个密码文件（几百字节），而且是自动创建的。
每次保存会触发一次构建，构建配额是 **500 次/月**，个人站完全够。

**Q：我能反悔吗？**
能。删掉 EdgeOne 的环境变量、撤销 Token，云端后台就彻底失联了，
本地的后台和你的网站一点都不受影响。
