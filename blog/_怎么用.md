# 怎么用这个文件夹写博客

这个 `blog/` 文件夹就是你的笔记库。用 **Obsidian 打开它** 写笔记；写完 `git push` 只是把笔记存进仓库，网站要更新还得跑一次 `npm run build` 再把 `dist/` 上传上去（见项目根目录的 `README.md` 第八节）。

---

## 一、第一次配置 Obsidian

1. 打开 Obsidian
2. 点「打开其他仓库」→「打开文件夹作为仓库」
3. 选中这个 `blog` 文件夹

以后就在这里写。Obsidian 自己的设置存在 `.obsidian/` 里，**不会**被发布到网站上。

---

## 二、写一篇新笔记

把 `_模板.md` 的内容复制到一个新文件里（新文件名随便起，比如 `TCP 三次握手.md`），然后开始写。

正文用 Markdown，另见项目根目录的 `README.md`。

---

## 三、文件开头的设置项（frontmatter）

文件最上面用两行 `---` 包起来的那一段：

```yaml
---
title: TCP 三次握手
date: 2026-09-28
category: 技术开发
tags: [网络, 面试]
summary: 一句话摘要，显示在卡片上。
cover: 封面图.png
draft: false
---
```

| 字段 | 作用 | 不写的话 |
| --- | --- | --- |
| `title` | 标题 | 用文件名（自动去掉 `.md` 和开头的日期） |
| `date` | 日期 | 先用文件名里的日期，再没有就用文件修改时间 |
| `category` | 分类 | 用所在的**子文件夹名** |
| `tags` | 标签，`[a, b]` 或换行写 `- a` | 空 |
| `summary` | 摘要，显示在 Blog 卡片上 | 空 |
| `cover` | 封面图文件名 | 自动生成一张带编号的底纹封面 |
| `pinned` | 写 `true` 就在笔记列表里**置顶**（排最前，标题带 📌） | 不置顶 |
| `draft` | 写 `true` 就**不发布** | 发布 |
| `slug` | 自定义网址里的 id | 由文件名生成 |

## 四、分类

**子文件夹名 = 分类名。**

```
blog/
├─ 技术开发/
│   └─ TCP 三次握手.md         → 分类「技术开发」
├─ 日常记录/
│   └─ 今天做了什么.md          → 分类「日常记录」
└─ 随手写.md                    → 分类「未分类」
```

Blog 页顶部的筛选按钮会自动跟着分类走，不用手动维护。

---

## 五、放图片

把图片放进 `blog/attachments/`，然后在笔记里用 Obsidian 的写法引用：

```
![[图片名.png]]
```

构建时会自动复制到 `media/notes/` 并转成正常的图片标签。

也可以直接用标准写法：`![说明](attachments/图片名.png)`

> 在 Obsidian 设置里把「附件默认位置」设为 `attachments` 文件夹，粘贴的图片就会自动进那里。

## 六、几件要知道的事

- **以 `_` 开头的文件不会被发布**（比如这个说明和 `_模板.md`）
- 标了 `draft: true` 的笔记不会被发布，可以放心写草稿
- **双向链接 `[[另一篇笔记]]`** 会变成能点的站内链接；`[[笔记名|显示文字]]` 可以自定义显示文字。找不到对应笔记时**不会报错**，只会显示成灰色虚线文字
- 数学公式**支持**：`$行内$` 和 `$$块级$$`，用 KaTeX 渲染（按需从 CDN 加载，正文里没有公式就不会去请求）
- **Mermaid 图表支持**：用 ` ```mermaid ` 代码块画流程图、时序图等（同样按需从 CDN 加载）
- **Dataview 支持常用子集**：`LIST` / `TABLE 字段1, 字段2` / `TASK`，可以配 `FROM #标签`、`FROM "文件夹"`、`SORT date DESC`、`LIMIT n`；`WHERE`、`choice()`、`dateformat()` 这类表达式和 DataviewJS **不支持**
- Obsidian 的注释 `%%像这样%%` 会被自动去掉

## 七、本地预览

1. 在项目目录里打开命令行（PowerShell），第一次先跑 `npm install` 装依赖（需要联网，只跑一次）
2. 以后每次跑 `npm run dev`：它会先同步一次内容，然后启动本地预览
3. 浏览器打开 <http://localhost:4321>

> 原来那些双击运行的 `启动网站.cmd` 之类的脚本**已经删掉了**，现在统一在命令行里用 `npm run ...`。

写完一篇笔记、在 Obsidian 里保存之后，开着 `npm run dev` 的话它**会自动同步**，回到浏览器按 **Ctrl+F5** 强制刷新就能看到新文章。

自动同步不灵时，回项目目录手动补一刀：

```bash
npm run sync
```

（`npm run dev` 和 `npm run build` 其实已经各自带了一次同步，所以平时不用手动跑。）

> 为什么要同步？因为 `blog/` 是原料，Astro 读的是加工后的数据文件。
> `npm run sync` 就是把 `blog/` 和 `img/` 加工一遍，几秒钟的事。

---

## 八、发布到网上

```bash
npm run build
```

生成 `dist/` 文件夹，把它里面的内容上传到你的服务器或对象存储就行。
详细的腾讯云部署步骤见项目根目录的 `README.md` 第八节。

> `dist/` 每次构建都会重新生成，不用手动维护。
